Every change has a blast radius.

Your agent sees the file it edited. MonoFlow sees every package that change reaches, tests them, and pushes only green.

Agents rarely fail at the code. They fail at the repo around it.

In a plain monorepo, an agentWith MonoFlow, it
greps the tree to guess who imports a packageasks graph query: every importer, in every module
tests one package and misses the dependent it brokeruns verify: exactly what CI would run for this change
reads pages of colored logs to find one failing linegets each break as file:line, with the line shown
pushes, then learns CI is redships a commit that passed CI locally, on that exact commit
polls gh run watch, paying tokens to waitends its turn; the result is delivered to it

Three commands. Edit to PR.

  1. Start monoflow start fix-rounding

    Its own worktree and branch, off the latest main. No two agents share a checkout.

  2. Verify monoflow verify

    Build, lint and test the changed packages and every dependent. Already running in the background once edits settle.

  3. Ship monoflow ship -m "fix: rounding"

    Returns at once. CI runs locally on the commit; only green is pushed and opened as a PR.

What your agents get

CI for this change, in one command

The changed packages run first, and their dependents once those pass. Results are cached by content. Failures main already has are reported but don't block. For Go, only packages that import the change run.

From an agent's run on opentelemetry-go

Nothing red reaches the remote

ship runs CI on the exact commit, in a clean checkout, and pushes only on green. Pushes to main are refused.

A map, not a grep

graph query <dir> lists every package importing it, across all modules, in about a second.

No polling

Hooks for Claude Code and opencode put CI results in the agent's context, and wake it when pending work finishes.

One worktree per agent

Sparse worktrees with their own dependencies, checkpoints outside Git history, and AST-level merges between agents.

Guardrails

Commits are refused when assertions disappear or secrets leak. Risk scores and proof receipts tell reviewers where to look.

Install

  1. Build

    Needs Go 1.22 or later. The result is one static binary.

    git clone https://github.com/M0xoo/monoflow.git
cd monoflow && make build

  2. Install into your repo

    Puts the binary at .agents/bin/monoflow, links it as ./bin/monoflow, and runs monoflow init.

    cd /path/to/your-repo
/path/to/monoflow/install.sh

  3. Affected-only GitHub Actions

    Optional. Remote CI runs only affected packages and skips work a local proof already covers.

    ./bin/monoflow init --setup-gh-actions
