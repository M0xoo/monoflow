Make your monorepo usable by coding agents.

MonoFlow gives agents like Claude Code, Cursor and Antigravity what they otherwise have to work out from raw files and noisy terminals: a map of the repo, a fast loop, an undo button, an isolated place to work, and a safe path to ship. Every answer comes back as compact JSON.

Without MonoFlow, an agent…

  • greps the whole tree to guess what depends on what
  • runs the full test suite and reads pages of colored logs
  • commits every failed attempt, or loses work it can't undo
  • edits the same checkout as you and every other agent
  • "fixes" red tests by deleting assertions
  • polls CI in a loop, spending tokens while it waits

With MonoFlow, it…

  • asks the dependency graph directly
  • checks only the affected packages and gets errors back as JSON
  • saves and reverts checkpoints without touching history
  • works in its own sparse worktree
  • gets stopped by the test integrity guard
  • pushes, moves on, and is notified when CI finishes

What MonoFlow provides

Six capabilities, all in one CLI. Each one replaces something agents are currently bad at.

01

A map of the repo

init finds your packages and their dependency graph. Agents can then ask what a package depends on, or what a change to a file affects, without crawling the tree. Large repos can check out just the packages a task needs.

monoflow graph query packages/core
monoflow graph impact packages/core/x.go
monoflow subset set --packages=billing
02

Feedback in seconds, as JSON

verify --affected checks only what the change touches, runs packages in parallel, and uses cached results when inputs haven't changed. Errors are normalized to file · line · col · code · message, with no ANSI codes or spinners.

monoflow verify --affected
monoflow cache status
03

Undo without touching history

Checkpoints snapshot the working tree with Git plumbing. Agents can try an idea, fail, and roll back in milliseconds, without commits in the log or stashes to clean up.

monoflow checkpoint save "hypothesis"
monoflow checkpoint revert
04

An isolated worktree per agent

Each agent gets a sparse worktree that contains only its packages, so parallel agents and humans don't collide. When two agents add code to the same file, MonoFlow merges at the symbol level instead of leaving conflict markers.

monoflow worktree create agent-42 --packages=billing
monoflow worktree sync --to=agent-42 --from=agent-7
monoflow worktree finish agent-42
05

Guardrails you can trust

Task boundaries say which paths an agent may change. The guard rejects diffs that weaken tests and scans for leaked secrets. Proof-of-work receipts and risk scores tell a reviewer how much attention a change needs.

monoflow task check
monoflow guard check
monoflow task prove task-42
monoflow review risk
06

A shipping path built for agents

Commit, sync and push without raw Git, and with main protected. PRs come with a risk tier and the list of affected packages. Pushing returns right away: CI results arrive later in an event inbox, so the agent never has to poll. When CI is red, ci health shows what broke, when, and which commit did it.

monoflow commit -m "fix: rounding"
monoflow pr create --title="fix: rounding"
monoflow events unread
monoflow ci health

The agent loop

monoflow init writes AGENTS.md and a skill file, so your agent follows this loop without extra prompting.

Install

Requires Go 1.22+ to build. The result is a single static binary with no runtime dependencies.

1

Build

git clone https://github.com/M0xoo/monoflow.git
cd monoflow && make build
2

Install into your repo

cd /path/to/your-repo
/path/to/monoflow/install.sh

This copies the binary to .agents/bin/monoflow and runs monoflow init.

3

Optional: CI integration

.agents/bin/monoflow init --setup-gh-actions

Adds GitHub Actions workflows for package caching and two-tier CI.

What init writes

.agents/monoflow.config.jsonDiscovered packages and dependency graph
AGENTS.md · .agents/rules/ · .agents/skills/monoflow/Instructions your agent loads automatically
.agents/task.jsonTask boundaries: allowed_paths, read_only_paths
.agents/quarantine.jsonFlaky tests kept out of the feedback loop

Commands

Every command prints JSON. Run monoflow with no arguments for full usage.
