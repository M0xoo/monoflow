Three commands. Edit to PR.

  1. Start monoflow start fix-rounding

    Its own worktree and branch, off the latest main. No two agents share a checkout.

  2. Verify monoflow verify

    Your packages' failures in seconds; every dependent checked in the background behind them. Re-runs only the test files your edits touched.

  3. Ship monoflow ship -m "fix: rounding"

    Returns at once. CI runs locally on the commit; only green is pushed and opened as a PR.

What your agents get

CI for this change, in one command

The changed packages answer first, in seconds; their dependents are checked in the background and the next verify includes them. Cached per check and per test file, so a re-verify runs only what your edits touched. Failures main already has don't block.

Nothing red reaches the remote

ship runs CI on the exact commit, in a clean checkout, and pushes only on green. Pushes to main are refused.

A map, not a grep

find "<text>" groups occurrences into code, tests and docs, without changelogs or generated files: 5 KB where grep prints 23 KB. graph query <dir> lists every package importing it.

No polling

Hooks for Claude Code and opencode put CI results in the agent's context, and wake it when pending work finishes.

One worktree per agent

Sparse worktrees with their own dependencies, checkpoints outside Git history, and AST-level merges of Go files between agents.

Guardrails

Commits are refused when assertions disappear or secrets leak. Risk scores and proof receipts tell reviewers where to look.

Live code or a pinned release.

Every in-repo dependency is one of two kinds of edge, and each consumer picks. monoflow version edges lists them all.

Source

The consumer points at the package's directory: workspace:, Go replace or go.work, a Cargo or uv path. The default.

A change to the package reaches the consumer at once. verify re-tests it, and an API break is fixed in the same change.

Pinned

The consumer points at a release snapshot under .agents/releases/<pkg>@<version>/.

Later changes do not reach it, and verify does not re-test it for them. It upgrades when it chooses, and its own checks run on the upgrade.

  1. version suggest moneyThe bump the exported-API diff requires: removed or changed symbols mean major.
  2. version bump money minorWrites the version and reports each consumer's impact. It rewrites none of them.
  3. version release moneyTags money@1.3.0 and tells each pinning consumer whether it is compatible or breaking for it.
  4. version pin ledger moneyCommits the snapshot, so any clone, IDE or CI builds it without MonoFlow.
  5. version upgrade ledger moneyMoves the pin to the newest compatible release and runs ledger's checks.

Releasing a version twice, or a package with uncommitted changes, is refused. Snapshots nobody pins are removed, and version check flags one that no longer matches its tag. With many agents, each records the bump its change needs (task changeset) and version apply applies the highest per package.

How it works

MonoFlow doesn't replace your compilers, test runners or CI. It decides what to run, where to run it, and how the agent hears about the result. Everything it knows is a plain file under .agents/.

  1. Graph

    Packages and their edges are read from the manifests already in the repo: go.mod, pnpm/npm/yarn workspaces, Cargo, pyproject.toml. A changed file belongs to the package with the longest matching path. The affected set is those packages plus every transitive dependent. For Go, go list runs in every module to find real importers.

    .agents/monoflow.config.json

  2. Worktree

    start fetches main and runs git worktree add -b agent/<id> from origin/main (--from-local for your local main). Caches and events are symlinked to the root. Dependencies are installed offline (pnpm) or linked. --packages narrows it to a sparse cone.

    .agents/worktrees/<id>

  3. Verify

    Changed packages run first, in parallel, while the dependents' upstream builds run; the agent's verify answers with their failures at once, or PENDING when they pass, and the dependents are checked in the background. Results are keyed by a SHA-256 of files, command and upstream keys, per check and per vitest test file, so unchanged inputs aren't re-run, and a reformatted file keeps its keys. A failure is re-checked against main: if main fails the same way, it's reported as pre-existing and doesn't block. Output is stripped to file:line with source context.

    .agents/cache/verify/

  4. Background

    A hook fires after each agent tool call. When edits have been quiet for 1.5s, verify starts in the background, keyed by HEAD plus the working-tree diff. Runs are never cancelled by newer edits: what they checked stays cached. When the agent asks about the same files, the result is often already there.

    .agents/verify/<key>

  5. Ship

    ship commits after the test-integrity and secret checks, then returns. A detached process checks the commit out cleanly and runs local CI. It pushes and opens the PR only on green, and only if the commit merges cleanly into main. On red or on a conflict, it records why and pushes nothing. After the push, a watcher reports a conflict if main later moves into one.

    .agents/outer_loop/ · refs/monoflow/proofs/<sha>

  6. Events

    A detached watcher polls gh so the agent doesn't have to. Results land as JSON files. Claude Code and opencode hooks add them to the agent's context, and the Stop hook waits on pending work and wakes the agent when something needs action.

    .agents/events/

Remote CI imports the proofs pushed by ship. Packages already verified locally on identical inputs count as cache hits, so CI runs only the rest.

Install

  1. Build

    Needs Go 1.22 or later. The result is one static binary.

    git clone https://github.com/M0xoo/monoflow.git
cd monoflow && make build

  2. Install into your repo

    Puts the binary at .agents/bin/monoflow, links it as ./bin/monoflow, and runs monoflow init.

    cd /path/to/your-repo
/path/to/monoflow/install.sh

  3. Affected-only GitHub Actions

    Optional. Remote CI runs only affected packages and skips work a local proof already covers.

    ./bin/monoflow init --setup-gh-actions
